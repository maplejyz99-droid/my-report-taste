# Contributing

Prefer fixes for demonstrated workflow failures over universal rules inferred from one example. Keep the skill entrypoint short and load specialist references only when relevant.

For a change, include a minimal non-private request or fixture, the observed problem, and the verification performed. Separate deterministic tests from factual/visual review and real rehearsals. Do not label all platforms supported after one local check.

Run the two unittest suites, library validation, and public-release check shown in README. Do not commit personal preference files, source decks, credentials, local paths, generated logs, or unlicensed assets. The sample data is intentionally synthetic; do not replace it with a private study.

By contributing, you agree to license your original contribution under the repository MIT license. Identify any third-party components and their license separately.
