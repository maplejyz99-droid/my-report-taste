# 小规模任务评测

当前状态：**已准备任务与判据，尚未运行有／无 skill 的代理对照**。单元测试、手工编写的 HTML 示例与 gallery 不能算对照实验，也不能据此宣称节省返工或 token。

## 第一轮：公开合成材料的预检

[cases.json](../examples/evaluation/cases.json) 固定四项任务：中文新作、单页修改、压缩主讲、只写双语讲稿。使用现有 source.json 和五页 demo.pptx，无需私人论文。它们先检查评测流程是否可执行；通过后再加入经许可的公开论文或脱敏真实任务，重点补齐公式、论文截图和复杂中文排版。

每个任务分别运行 skill-on / skill-off，各先做一次；出现值得比较的差异后，再各重复至少三次并报告各次结果。少量样本只用于找问题，不给统计显著性或普遍收益结论。

## 对照条件

- 固定同一个模型及版本、推理档位、制作后端、字体、工具权限、原始材料、时间／token 上限和用户提示。
- 每次使用独立干净目录与新会话；复制同一份输入，保留输入哈希。不共享前轮答案、记忆或已改好的成品。
- on 组启用本 skill，off 组不加载本 skill；制作与渲染工具仍相同。若宿主无法可靠隔离用户级 skill／偏好，不把该次称为干净 A/B。
- 用户任务相同；只改变是否启用本 skill。不要给对照组故意简陋的提示，也不要给 on 组额外的事实或排版成品。
- 把 case prompt 和原始输入交给生成代理。预期结果与评分记录交给独立评价阶段，避免把答案泄漏进生成过程。
- 不自动启动批量模型调用、上传私人材料或消耗付费渲染资源。确认预算、材料许可和运行环境后才实际执行。

## 每次保留什么

模型／工具版本、输入与 skill 提交哈希、原始提示、执行记录、最终文件、实际渲染、关键人工修改，以及开始／结束时间。token 与费用仅用平台真实记录；没有记录就写 unknown，不用估计冒充测量。

评价先看：关键事实错误、漏掉的关键证据、未经要求的修改。再看最终尺寸下的可读性、讲述连贯性、已声明偏好符合度。最后记录达到接受所需的人工修改次数、修改量、总耗时与 token。不要以“遵循规则更多”直接当作成品更好。

局部修改比较未受影响页的文本、备注、页序和渲染；PPTX 重新导出可能改变内部 ID／元数据，不能仅凭整包哈希变化断言越权。scripts-only 任务则必须保持输入 deck 字节不变。

将两个版本匿名为 A/B，在相同尺寸下比较；评价者不知道哪组用了 skill。明确的用户偏好只在两组都拿到同样偏好时计入标准。必要时接受平局，保留具体问题，而非用一个总分遮住事实错误。

## 结果记录模板

每次填写以下短记录即可，无需额外评测平台：

```json
{
  "case_id": "edit-one-page",
  "condition": "skill-on",
  "run": 1,
  "status": "not_run",
  "model_and_backend": null,
  "input_hashes": {},
  "skill_commit": null,
  "critical_fact_errors": null,
  "unrequested_changes": null,
  "human_revision_rounds": null,
  "elapsed_seconds": null,
  "tokens": null,
  "blind_review_findings": [],
  "artifact_locations": []
}
```

完成真实运行后再总结：哪些规则改变了决策，哪些只是增加阅读／文件／工具调用。只有复现了问题才修改相关规则；不把本评测协议变成每次普通做 PPT 的必经手续。

方法参考：[OpenAI — Testing Agent Skills Systematically with Evals](https://developers.openai.com/blog/eval-skills)。此处采用其“小任务集、执行记录、结果与效率分开检查”的思路，不意味着仓库已完成那些评测。
