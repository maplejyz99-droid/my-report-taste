# 变成你自己的汇报品味库

## 从局部偏好开始

不必接受作者全部审美。给 agent 一份你有权使用的参考，明确喜欢的是叙事、表格、密度还是配色，并说“收藏这个部分”。例如：

> 收藏这份汇报的大幅证据图和直接标注，不收藏它的绿色主题。主要用于实验组会。

当前成品临时选择不等于永久偏好；只评价或制作不会自动修改长期库。

## 保存自己的偏好

先分清三个层次：内容任务是 explain／progress／compare；证据与密度由材料、受众和阅读方式决定；颜色与布局再从模板或预设选择。可以给进展汇报借用酒红外观，也可以给技术讲解借用绿色外观，不必连带参考材料的目录。

仅换外观时用 `--visual`，完整复用某个参考组合时用 `--preset`。例如 `route --content progress --visual academic-oral-wine` 保持进展任务，不因酒红呈现变成论文 Oral。[具体接口](../skills/my-report-taste/references/routing.md)

在汇报项目中自行建立 `.report-taste/profile.md`；只写与当前项目有关的规则。也可以在已安装 skill 内建立 `references/local-profile.md` 作为个人默认。项目规则优先，当前任务与官方模板更优先。

```markdown
# 我的汇报偏好
## 已确认
- 研究组会：结论与完整证据同页，不机械拆成三张卡片。
- 视觉：采用我提供的实验室模板。
## 避免
- 为统一外观重画已经清晰的论文图。
## 仍在尝试
- 何时需要独立导航页。
```

这些本地文件被公开仓库的 `.gitignore` 和打包逻辑排除，但忽略规则不是访问控制；在任何新仓库中仍需检查提交清单。

## 扩充卡片

让 agent 按 skill 中的 collection-schema 建立新卡。来源事实、使用者确认、设计推断和许可状态分开；不要把一张参考图推断成全局偏好。新增后运行库校验。

作者示例库的 approved／confirmed 不会自动变成你的认可。负向卡也只是作者的反例，可用于比较，不是普遍禁用名单。你可以建立自己的候选、认可与拒绝记录。

## 分享你的改动

只提交通用规则、可公开的最小测试和原创／授权示例。先去掉原话中的身份、项目、路径及未公开结果。第三方素材保留原许可；未知授权的原始图表和模板不进入发行包。
