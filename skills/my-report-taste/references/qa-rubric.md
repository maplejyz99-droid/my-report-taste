# 汇报验收：比对、判断与未验证项

先检查内容，再检查呈现。不再用 100 分量表或“80 分可交付”放行：自主判断可以发现问题，但数字不构成论证、用户授权或成品正确性的证据。

## 适用范围

- 幻灯片维护 `slide-plan.md` 与 `verification.md`；PPTX 运行下述机器检查，HTML／Marp 按真实页面提取和渲染比对。
- 报告型 PDF 按章节、图表和来源比较，不强制建立 slide ID 或生成 PPTX。
- 直接 Markdown 核对摘要、标题层级、主张与来源，沿用既有大纲即可；没有图形产物，不执行空转的视觉工具。
- 完整新作全量验收；局部修改重检受影响页及共享母版／字号／页序等影响范围，并记录哪些证据沿用上一已验收版本。
- 这一范围规则同样适用于论文 Oral 等专项工作流。旧证据缺失或不可靠时，补足实际交付需要的检查；新作无历史基线时版本差分为“不适用”。工具天然全量导出只是实现方式，不等于必须重做全部内容审读。

## 制作前：计划预检与内容取舍

```bash
python3 scripts/verify_deck_plan.py PLAN.md
python3 scripts/verify_deck_plan.py PLAN.md --previous-plan PREVIOUS_PLAN.md
```

脚本检查计划字段、稳定 ID 和角色；改版还输出受保护字段及逐页 diff。`plan-only` 不检查成品，不得将其 PASS 报告成文件／视觉检查通过。

读完整标题链、主张、证据与收尾，判断中心是什么、证据篇幅是否对应重要性、主线是否实际完成取舍。用户列出的多个问题不必等权展开。记录发现及具体修改，不再给“叙事”打一个不可复核的高分。

### 排版前的内容编辑检查

在既有大纲与计划中检查，不新增表单或 AI 味评分：更换项目名后仍通用的段落是否缺少具体对象、操作与条件；是否为凑三点、完整目录或对称模块增加内容；删页是否损失必要理解／证据；关键难点是否获得相称篇幅。空泛内容回到源材料核对，不靠替换形容词补救。

## 制作后：确定性比对

```bash
python3 scripts/verify_deck_plan.py PLAN.md DECK.pptx
python3 scripts/verify_deck_plan.py PLAN.md DECK.pptx \
  --previous-plan PREVIOUS_PLAN.md
```

以下不一致必须修复；通过只表示这些比对未发现错误：

- 当前计划确实存在于成品目录，标题文本、可见页数、稳定 ID 和 `main / optional / backup` 与成品一致。
- 三个受保护字段合法；推荐的固定文本出现在 `main` 页正文，而非仅藏在备注或附录。
- 改版保留上一版基线；`protected_diff` 和 `slide_diff` 列出表头及逐页增删、顺序、角色、标题、主张、证据、衔接和已填写的职责／密度变化。

备注检查默认 `required`。旧稿无法补标记时可用 `--notes-policy warn`，只降级缺失；已有标记与计划矛盾仍失败。`ignore` 表示明确关闭检查，必须列为未验证。标题文本存在不证明它处于标题位置，推荐字符串存在也不证明听众能读到；这两点还要渲染核查。

## 必须核对来源的授权与事实

下列是人工／代理核对责任，不是上述脚本已经验证的事实：

- 菜单型的 `confirmed` 是否对应用户明确选择；受保护内容改变是否有本次适用的授权。把用户原话或可定位记录与变化对应写入 `verification.md`，不能把字段自身当证据。
- Reviewer proposal 是否仍保留 proposal 身份；“继续”没有消除尚待用户决定的分叉。
- 主张、数值、比较口径和停止条件是否与原始证据或用户已确认事实一致；派生 Markdown 与成品互相一致，不等于它们都正确。
- 讨论文档／实验进展转汇报时，按 [research-progress-workflow.md](research-progress-workflow.md) 对照已确认意图与当前实验范围；核查页面实际显示的证据能否支持标题，而不只查数字是否存在。

发现事实错误、未经授权的立场替换或核心证据遗漏，停止相应交付并修复／请求决定。标明待决项影响的页面与依赖，不受影响的已授权工作继续完成。已经明确授权的常规制作和修改无需重复确认。

## 判断项与可检查证据

完整标题链、各页角色／职责、证据清单、受保护字段与逐页 diff 写入 `verification.md`。交付消息只集中说明重要结论与未解决项；不要求用户逐页批准，也不强制普通任务另找 reviewer。

对判断项记录“发现 → 对应页／源证据 → 处理或保留理由”，而非分数：

- 叙事：标题、证据与衔接是否表达中心与推进；问题是否获得回答；仅需推荐时检查推荐落点，重要边界是否贴近受影响主张。定义、方法和设置标题不要求结论句。
- 密度：最终尺寸下能否读清关键证据；主次是否一眼可定位；参考密度按页面职责适配，不靠统一缩字或机械留白。
- 节奏：连续页面是否为了方便生成而复制等权卡片；有意重复的实验比较序列可以保留，不追求逐页换花样。
- 图表：图／表／公式／原生机制图均可充当证据，类型服从论证；单位、阈值、来源、坐标、图例与比较口径完整。

成品后检查：具体内容是否被润色为通用口号；图表、公式或原始素材是否被无必要替换为卡片；重复布局是在帮助比较还是仅方便生成；图标、总结条或箭头是否提供实际信息。允许必要的重复与朴素标题，不通过逐页换花样或禁用某个词来证明自然。

脚本的疑问句、重复文本和无图片页是诊断信号，不是失败阈值。`repeated_layout_signatures` 只统计对象数量，不能证明几何布局相同；纯文字页也可能含有效公式或原生示意，必须看实际内容。

## 呈现与文件检查

- 按实际选择范围检查 gate：完整组合检查兼容的叙事与呈现，单选叙事不检查颜色，仅换外观不改写主线或结论。固定章节／页型配额不作放行条件；无论选择如何，事实与证据可读性仍要检查。
- 原尺寸检查文字、公式、图表、来源、页码：无越界、遮挡、裁切、过小、异常换行或上下标错误；缩略图检查全篇焦点、色彩与节奏。两者不能互相替代。
- 使用实际交付媒介的渲染器：HTML 在浏览器，PPTX 在演示文稿渲染器，PDF 在 PDF 渲染器。只验证真实交付的版本，不为跨媒介检查额外转换文件。
- 中英文字体检查地区字形、字重、数字与单位、回退和嵌入；不以源文件预览替代导出验证。
- 系统页运行 `python3 scripts/color_qa.py --policy strict-ui <images>`；真实素材页用 `material-aware` 并按需遮罩。机械色相不替代验色，灰度检查不替代正常色彩检查。
- PPTX 派生 PDF 运行 `python3 scripts/verify_pdf.py OUTPUT.pdf --source-pptx INPUT.pptx`；报告型 PDF 用实际源文／预期页数核对。检查字体、文字提取、分页和渲染；静态终态不能依赖动画才成立。

`verification.md` 应能定位计划、基线、实际成品及执行过的命令／输出，区分：已验证、发现问题、未运行或不适用。外部主讲人试讲与目标设备测试无法执行时据实报告。视觉缺陷未修复、内容比对失败或决定未获授权时不能冒称完成；环境限制可明确列为未验证并给出可用替代。

## 库本身的维护检查

仅更新本 Skill 时运行，不作为每份普通 PPT 的额外手续：

```bash
python3 scripts/library.py validate --strict
python3 -m unittest discover -s tests -p 'test_*.py'
```

测试验证机器门禁的行为；库校验验证 ID、路由、gate 和资产引用。两者都不能证明新模型生成的整份汇报已经达到用户品味，仍需真实成品验收。
