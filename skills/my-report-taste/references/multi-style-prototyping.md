# 多路线原型操作指南

只在用户明确要求多版本、探索或自我迭代时启用。普通制作先选择最合适的一条路线，不机械增加版本。

## 1. 先定义差异轴

每版至少在以下三项存在实质差异：

- 受众或目标决策。
- 阅读距离、是否有演讲者、使用时长。
- 页面密度、叙事节奏、主要证据形式。
- 主视觉系统与字体角色。
- PPTX、PDF、HTML/video 等媒介能力。

只有颜色不同不构成新路线。

## 2. 路线卡

每版在制作前记录：

- `audience`
- `decision`
- `reading_mode`
- `duration_or_page_budget`
- `density_level`
- `main_system`
- `supporting_ids`（最多两个）
- `type_system`
- `output_format`
- `known_dependencies`

## 3. 推荐覆盖面

- 演讲型：远距离、结论先行、低至中密度。
- 编辑型：高对比、强节奏、管理层或发布场景。
- 独立阅读型：中高密度、同页证据闭环、稳定导航。
- 文档型：仅当需要正式归档、打印或无演讲者阅读时增加。

## 4. v1 → v2

1. 完成可读的 v1，不追求先把所有细节磨平。
2. 按 `qa-rubric.md` 比对与检查，记录最影响结果的问题及页码／证据，不用自评分数放行。
3. v2 只处理最重要的问题，保留 v1 作为证据。
4. 重新执行几何、字体、文本、逐页和缩略图检查。
5. 用户反馈后再决定某路线是候选、确认、验证或淘汰。

## 5. 命名与交付

- 使用稳定路线名，例如 `technical-light`、`dark-editorial`、`dense-board`、`dense-report`。
- 文件目录按 `route/v1` 与 `route/v2` 分开；失败导出放 `diagnostics/`，不得覆盖最终文件。
- 总入口列出各版场景、推荐顺序、最终文件与已知限制。
