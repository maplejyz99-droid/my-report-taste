# 配色实现与验收流程

这份流程用于把已收藏的配色参考落实为 PPT / PDF，而不是从参考中随意挑几种醒目颜色。

脚本依赖 Pillow；环境缺失时按根目录 `requirements.txt` 安装。缺少依赖会给出明确错误，不静默跳过验色。

## 1. 先分清来源与实现

- 来源配色卡描述参考材料实际如何使用颜色。
- 生成稿反馈卡描述 Codex 是否正确转译；生成失败不自动推翻来源偏好。
- 先选一个主配色卡，再定义项目语义，不把多个来源的颜色平均混合。

## 2. 从代表页抽样

至少覆盖：封面 / 章节页、普通内容页、图表页、表格或流程页、风险或异常页。记录：

- 背景、表面、正文、辅助文字、边界与网格。
- 主色的深 / 中 / 浅 / 洗白阶。
- 例外色出现的位置、次数和近似面积。
- 跨页节奏：哪些页允许全幅主色，哪些页必须回到中性底。

抽样值是重建证据，不宣称为来源官方品牌 token。

## 3. 建立语义 token

最小角色为：`canvas`、`surface`、`ink`、`muted`、`line`、`primary`、`primary-mid`、`primary-pale`、`exception`。深色体系再增加 `cover-black`、`surface-strong` 和 `grid`。若参考背景存在空间明度变化，进一步拆成 `light-field-edge`、`light-field-base`、`light-field-glow`；这些 token 是取样锚点，不得任选一个铺满全页。

颜色只编码当前 / 次要 / 风险 / 未知等语义。方法名称、部门或页码本身不是增加色相的理由。

## 4. 面积门禁

- 普通内容页通常只有一个主色族；显著饱和色相不超过两个。
- 第二色相必须是异常、风险或唯一机制焦点，并同时有文字 / 线型 / 位置编码。
- Goodpatch 内容页的珊瑚风险色通常低于页面面积的 2%。
- LENZ 生成路线默认不用饱和黄 / 金；若未来启用唯一暖色焦点，低于页面面积的 1%，不得填充普通卡片、整条曲线或一组流程节点。
- 封面或章节幕封可以全幅主色，但内容页不得照搬同等饱和面积。
- 同级比较卡 / 表格行默认共享一个 `surface`；选中、风险与未知先通过字重、明度、标签、窄色条和位置编码，彩色整块填充不作为默认状态色。描边必须区分组件类型：独立卡片可用低对比细边，连续表格不得使用整行闭合选中框。

## 5. 深色光场与统一表面门禁

采用 `CLR-003` 或其他非纯色暗底时，额外检查：

- 对无内容背景或背景可见区做九宫格取样。九格应包含多个近黑 / 主色明度，而不是近似同一颜色；最亮格仍必须明显暗于正文和主要数据表面。
- 原尺寸查看时应能感到暗角与局部照明；缩略图中不应先看到云纹、光束、颗粒、渐变带或全页方格。
- 比较组件移除文字后应看起来属于同一套表面系统。若仅靠底色就能猜出每个方法名称，说明颜色被错误绑定到类别。
- 执行“围合预算”检查：连续表格最多一层整体围合，行间只保留内缩 1 px 左右的低对比发丝线；不得同时出现整表外框、逐行边框和选中行闭合框。
- 选中项优先使用更亮 / 更粗的关键文字和直接状态标签；需要额外定位时只用短边导轨。风险项优先使用 4–6 px 局部窄色标和状态文字。整行风险色、交替行色、方法专属色与闭合选中框默认判为失败。

## 6. 两档机械验色

先把所有页面渲染为 PNG。脚本提供两档策略：

- `material-aware`：默认。照片、截图、热图和原始证据可保留真实颜色；超过色相启发式时只给 WARNING，不导致失败。
- `strict-ui`：用于无照片／截图的纯系统页；显著色相超过预算时返回失败。

纯系统页运行：

```bash
python3 scripts/color_qa.py --policy strict-ui --bin-width 45 slide-*.png
```

含素材页运行默认策略，并可用归一化坐标排除已知素材区：

```bash
python3 scripts/color_qa.py --policy material-aware \
  --mask 0.48,0.18,0.47,0.68 \
  slide-07.png
```

大量页面可使用策略文件，通过文件名 glob 批量指定策略与遮罩：

```json
{
  "rules": [
    {"pattern": "slide-0[1-3].png", "policy": "strict-ui"},
    {"pattern": "slide-1*.png", "policy": "material-aware", "masks": [[0.46, 0.16, 0.50, 0.72]]}
  ]
}
```

```bash
python3 scripts/color_qa.py --policy-file color-policy.json slide-*.png
```

遮罩坐标依次为 `x,y,width,height`，均相对页面宽高归一化到 `[0,1]`。脚本忽略低饱和和过暗像素，默认把占未遮罩页面至少 0.75% 的色相视为显著，并以两个色相为预算。它只能发现彩虹化或面积异常，不能证明配色好看。

## 7. 人工视觉检查

- 逐页原尺寸检查主色是否过重、暗部是否糊成一片、异常色是否抢走主结论。
- 查看缩略图总览，确认跨页主色节奏稳定且不同路线真的对应不同参考。
- 临时去色检查，确认层级不依赖颜色单点故障。
- PPTX 派生 PDF 再渲染一遍，检查字体替换或透明度转换是否改变视觉重量。

若机械检查通过但用户仍认为丑，以用户完整成品反馈为最高证据，并新增或更新 `generated-output / rejected / negative` 模式卡。
