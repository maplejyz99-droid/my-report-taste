## 设计推断

- 吸引力的核心不是某一个“炫技特效”，而是镜头层、页面层和对象层共享同一空间逻辑。
- 拼贴开合建立整套材料的“地图感”；对象级联负责控制注意力；图表路径绘制负责把证据过程显性化。
- 动效应该保存为可复用 recipe，而不是按页面录死：`camera-mosaic`、`kinetic-title`、`kpi-cascade`、`path-draw`、`center-orbit`、`mosaic-return`。

## 内容与叙事规则

- 开场拼贴只负责建立全局与局部关系，不在缩略状态要求读者阅读小字。
- KPI 先出现指标名与比较框架，再增长数字；不能先用夸张数字吸睛、随后才解释口径。
- 图表按“坐标 / 预算线 → 数据路径 → 关键点 → 注释”顺序进入。
- 中心—外围页先稳定中心对象，再展开关系线和外围模块；进入顺序必须与实际逻辑一致。
- 每个章节最多安排一个高强度镜头动作，正文页以对象级联和局部路径动画为主。

## 视觉与版式配方

- 固定一套 \(16{:}9\) 画布与稳定安全区；拼贴使用等比例缩略页，不重新排版。
- 镜头层：整套拼贴缩放到目标页，缓入后快速收束；离场反向缩回。
- KPI 层：卡片错峰约 `80–140 ms`，数字递增与卡片落位同步，最后一个重点卡可提高饱和度或面积。
- 图表层：路径从左向右绘制，面积填充跟随；重要节点在路径到达后再出现。
- 系统层：中心对象保持原位，关系线先延伸，外围卡片随后沿对应方向进入。
- 强度分级：封面 / 收尾为高强度，KPI / 图表 / 系统为中强度，普通说明页为低强度或静态。

## 媒介适配

- HTML deck：优先实现方式，可精确控制连续镜头、对象时间线、路径绘制和重播；需支持键盘、触控、`prefers-reduced-motion` 与静态终态。
- PPTX：可用 Morph、Zoom、路径擦除、数值分步与对象动画近似；不承诺完全复刻网页级连续镜头。
- MP4：用于稳定播放和异地展示；必须保留可复现的 HTML 或 PPTX 源文件。
- PDF：只使用每个动效段落的静态终态，不把中间帧直接当页面。

## 反模式与边界

- 不复用 Firmwise 的紫色品牌配色、人物照片、Logo、文案或页面布局成品。
- 不给每个元素添加不同的飞入方向；一页最多一个主 recipe 和一个辅助 recipe。
- 不让循环粒子、光斑或持续漂浮抢占数据阅读。
- 不用动效掩盖事实不确定性、图表坐标误差、文字溢出或版式本身的薄弱。
- 不把网页动画等同于原生可编辑 PPTX；交付时必须说明载体能力边界。

## 验收标准

- 开场能清楚感知“整套 → 目标页”，收尾能回到“目标页 → 整套”。
- KPI、图表和系统页各有与语义匹配的不同 recipe，但整套缓动、方向和节奏一致。
- 暂停在任意终态时，标题、数据、标签与关系都完整可读。
- 禁用动效或导出 PDF 后，信息层级仍成立。
- 配色继续由当前汇报选用的已批准颜色模式决定，不自动继承来源紫色。
