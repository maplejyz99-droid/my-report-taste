## 设计推断

- 该模式的核心是 `stable geometry + contrast gating`：空间位置不变，只开放当前语义单元的视觉带宽。
- 完整上下文让听众知道当前代码位于哪一层；退暗让上下文存在但不争夺注意力。
- 聚焦单位应是一个可口头解释的逻辑段，如输入、守卫条件、核心更新、异常处理或输出，而不是固定一行。
- 最后一步可回到“关键输入 + 核心逻辑 + 输出”三段同时可读，帮助听众重新合成整体。

## 内容与叙事规则

1. 先给完整代码的静态总览，让听众知道函数、类或算法的边界。
2. 按因果顺序划分 `3–6` 个语义段：入口／配置 → 状态或数据结构 → 核心分支／更新 → 异常或边界 → 输出。
3. 每一步只聚焦一个主语义段；确需解释依赖时可同时亮起两个不连续短段，并用同一讲述句连接。
4. 讲解文本不复述代码字面值，应回答“为什么这样写、它改变了什么、失败时会怎样”。
5. 单页代码过长时先删去无关 import、日志和样板；投影型页面优先控制在约 `12–24` 个可见代码行。
6. 最后一态至少保留核心调用与结果的因果对应，不能停在只有内部实现而没有输出的状态。

## 视觉与版式配方

- 代码块占主体，标题与一句解释留在独立区域；讲解时不移动代码块、不改变字号、不重新换行。
- 活跃行段使用正常文本明度与完整语法色；非活跃行建议降至约 `22%–35%` 的感知明度，但行号、缩进和结构仍须可辨。
- 当前段可增加极轻的表面明度或左侧细导轨；不要同时使用粗框、荧光底、箭头和放大四种强调。
- 过渡建议 `180–320 ms` 的透明度缓动；不做垂直位移、缩放或逐字符打字。
- 浅色主题时把逻辑反转为“活动行深色、非活动行浅灰”，继续由 `CLR-002` 等当前主配色控制语法强调。
- 代码字体使用清晰等宽字体；中文解释与代码保持明显字体角色分离。

## 媒介适配

- HTML deck：优先使用 Reveal.js 的分步行号高亮或等效状态机；需支持键盘前后切换和 `prefers-reduced-motion`。
- PPTX：复制同一页形成连续状态或使用 Morph；所有代码对象位置、字号与换行完全一致，只调整各行文本明度。若需可编辑，按逻辑段拆成重叠文本层，而不是整块截图。
- PDF：将最重要的 `2–4` 个状态输出为连续页面，或使用一个完整代码块加 `2–3` 个编号注释；不能只保留某个中间高亮而失去上下文。
- 会后阅读稿：补充完整代码链接、文件路径或行号范围；页面只展示讲解所需摘录。

## 反模式与边界

- 不逐步隐藏未讲代码，使听众失去函数整体结构。
- 不让代码块在每一步重新换行、滚动或改变裁切范围。
- 不用红、黄、绿同时承担“当前行、错误、成功、警告”等多个竞争语义。
- 不把 (40+) 行真实文件整体缩小塞进一页；应提取可解释片段并标明来源行号。
- 不逐字符打字，也不把终端光标闪烁、扫描线或发光描边当作代码解释。
- 不因来源使用深色主题就强制所有组会代码页变成黑底；版式与当前汇报主系统保持一致。

## 验收标准

- 快速连按前后键时，代码几何位置、行号、换行和语法 token 不发生跳动。
- 每一态都能用一句话命名当前逻辑段，并能明确回答该段在整体中的作用。
- 非活动行仍可辨认结构，但不会与活动行争夺第一注意力。
- 最后一态能把调用、结果或关键更新重新关联起来。
- 禁用动效或导出 PDF 后，阅读顺序和代码因果关系仍完整。
