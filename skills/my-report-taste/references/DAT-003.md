## 设计推断

- 定位地图在汇报中应被当成“空间证据画布”，不是背景纹理，也不是替代通用地图应用。
- 制作顺序应是：先定义空间问题与视野，再决定哪些标记必须出现，随后弱化底图，最后添加说明与来源。
- 底图的视觉权重必须低于结论标记；默认去饱和或使用浅灰 / 浅色底图，只把一到两个重点点位、路线或区域设为主色。
- 直接标签优先于依赖图例来回查找；图例用于次级类别或较长解释，tooltip 只作为 HTML 增强。
- 固定视野不是缺点，而是汇报叙事的一部分；如果一个视野无法同时解释全局与局部，应使用 inset map 或拆成总览 + 局部两页。

## 内容与叙事规则

1. 先写一句空间结论，例如“训练节点集中在同一 NVLink 域内”或“样本来自三个不同气候区”，再决定地图范围。
2. 每页只回答一个主要地理问题：在哪里、如何连接、覆盖哪里、从何处到何处，不能同时承担完整地理数据库浏览。
3. 点位分为三级：结论点直接高亮并标注，证据点正常显示，背景参照点弱化或删除。
4. 路线只在方向或流量重要时使用箭头；普通关联线不添加无含义箭头。
5. 区域填充使用低透明度，边界与重点保持足够对比；重叠区域必须有明确层叠顺序。
6. 标题、口径、时间范围、数据来源和地理底图来源在静态导出中可见。

## 视觉与版式配方

- 布局 A：左侧 `28%–34%` 结论 / 图例 / 说明，右侧大地图证据画布。
- 布局 B：全幅地图 + 左上结论块 + 右下或下方图例；只用于标记较少且标签不拥挤的页面。
- 底图：中性浅灰或当前配色的极浅同色阶；道路、建筑、水域和边界仅保留解释所需图层。
- 标记：重点主色实心，普通点白底描边，背景点低透明度；标签优先贴近点位，冲突时使用短引线。
- 路线：连接线 `1–2 px`；流量箭头才使用宽度或锥度变化；虚线只表达计划、间接或不确定关系。
- 区域：填充透明度通常低于边界；避免多个高饱和色块盖住底图文字。
- inset map：只在局部视野失去上级地理语境时添加；不得成为第二张竞争主地图。

## 媒介适配

- PPT / PDF：默认固定视野、直接标签和静态图例；不依赖 hover、自由缩放或在线瓦片。地图应导出为矢量或高分辨率静态图。
- HTML deck：可保留有限交互，但默认锁定拖动与滚轮；若提供缩放，应有明确控件，并保证静态 fallback。
- 纵向 / 小屏：减少非关键标记，给长标签制作短版本，必要时把解释移到图例，并使用更高的地图画幅。
- 动效：可以按“底图 → 路线 / 区域 → 重点点位 → 标签”顺序揭示；静态终态必须独立成立。

## 反模式与边界

- 没有地点、路线、区域或空间比较时，不使用地图。
- 不把彩色底图与彩色标记同时设为高对比度；底图不是主角。
- 不在 PPT / PDF 把关键事实只放进 tooltip。
- 不使用过多行政区、道路、建筑和 POI 图层制造“专业感”。
- 不让点位标签压住重点路线、右上控制区、标题或地图边缘。
- 不把可缩放、可拖动当成质量本身；自由探索需求应改用交互式 symbol map 或独立数据产品。

## 验收标准

- 一眼能回答“这张地图要证明什么”，而不是只看见地名集合。
- 重点标记、普通证据与背景参照形成清楚的三级层次。
- 所有核心标签在目标媒介中可见且不重叠；长解释有图例或侧栏承接。
- 视野、投影、旋转、比例尺和 inset map 都有明确理由。
- 禁用网络、交互和动画后，地图仍能读懂；静态导出包含来源与必要口径。
- 仅当用户在真实汇报中确认此地图模式有效时，才把状态从 `candidate` 升级为 `approved` 或 `validated`。
