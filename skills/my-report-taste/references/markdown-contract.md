# Markdown 汇报源契约

## 目标

让 Markdown 成为可追溯的内容源，而不是把最终 PPT 或 PDF 的坐标和样式硬编码进正文。保留完整事实，同时显式区分核心结论、证据、限制和附录候选。

## 结构

- 使用唯一的一级标题作为文档主题，并用清晰的二、三级标题表达论证层级。
- 在开头给出摘要或关键结论；不要要求读者读到最后才知道汇报结论。
- 每个核心结论附近放置支持证据、适用条件和来源。
- 把完整参数、扩展实验、长表格和补充引用放入明确的附录区，而不是从源文档删除。
- 保持术语、数字、单位、数据口径和时间范围一致。
- 公式使用目标环境支持的 LaTeX；复杂表格优先改为列表或独立数据文件，避免窄窗口横向溢出。

## 派生页面地图

在制作 PPT 或 PDF 前，从 Markdown 派生独立页面地图，至少标记：

- `must-say`：汇报必须出现。
- `evidence`：支持主张的图表、数字或引用。
- `context`：理解所需背景。
- `risk`：限制、不确定性与反例。
- `appendix`：现场可跳过但需要保留。

除非用户要求，不要为了分页在原始 Markdown 中插入大量媒介专属标记。若需要固定切片，可以在派生副本中使用明确分隔符，并说明其只服务特定输出。

## 直接用 Markdown 汇报

- 让标题和每节首句承担导航作用。
- 用简短摘要、引用块、列表或局部强调突出重点，但避免整段加粗和连续高亮。
- 长章节先给结论，再给证据与细节；现场可折叠或跳过补充章节。
- 图片和图表紧邻解释文字，并提供可理解的标题、替代文本和来源。

## 验证

检查标题层级、链接、图片路径、代码块、公式、表格、脚注和导出后的分页。若 Markdown 会导出为 PDF 或 PPT，最终仍必须按对应媒介契约进行视觉验证。
