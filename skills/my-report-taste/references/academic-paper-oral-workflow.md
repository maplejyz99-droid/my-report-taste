# 学术论文 Oral PPT 工作流

## 适用范围与优先级

本工作流用于学术会议 Oral、论文组会、单篇论文讲解，以及以一篇论文为主体的答辩章节。内容任务通常为 explain；任务分类见 `content-modes.md`，它不是额外必填文档。先执行 `ppt-contract.md`，再执行本文件；若用户指定 `NAR-* / GRD-* / CLR-*`，把它们作为叙事、密度和颜色约束叠加使用。

会议官方模板、用户提供的母版和明确的会务要求优先决定画幅、Logo、页眉页脚、字体兼容和视觉皮肤。本工作流主要决定论文理解、内容取舍、证据组织、方法解释和验收，不把一次会议的品牌样式固化为长期偏好。

普通“学术 Oral”只启用本内容工作流，不自动选择 `NAR-001 + GRD-010 + CLR-010`。只有用户明确选择对应路线才叠加其样式；与官方模板冲突的配色 gate 不适用，仍保留兼容的证据与叙事要求。

以下完整制作流程用于新作或实质性内容重构。局部修订沿用既有理解稿、计划和可信验收证据，按 `qa-rubric.md` 检查影响范围；只读分析不生成文件。“确认输入”先核对已知信息，不表示每项都要用户重新批准。

## 成功定义

汇报结束后，听众应能复述五件事：论文解决什么问题、现有方法为何不足、本文贡献是什么、核心机制如何工作、主要证据与适用边界是什么。

PPT 不是论文逐页缩写，也不是 UI 作品集。视觉设计必须帮助听众理解论文的主张、依赖关系和证据，不得为了页面“像成品”而增加无来源的模块、口号、箭头、卡片或机制图。

## 开工前冻结输入

开始内容制作前确认或保守假设以下条件，并记录未知项：

- 听众背景、汇报语言和术语保留方式。
- 可用时长、问答是否另计，以及是否必须提前提交。
- 投影比例、官方模板、字体／媒体限制和提交格式。
- PPT 是配合主讲，还是需要会后独立阅读。
- 最终主讲人是否为制作者本人。若不是，页面和备注必须支持移交，不得依赖制作者脑中的隐含理解。

页数由时长、证据量和跳过策略共同决定，不设置机械固定值。允许内容略长，但必须把 `main / optional / backup` 分清，使主讲人可以安全快讲或跳过，而不会破坏论证链。

## 先理解论文，再写幻灯片

在打开 PPT 之前，先形成一份可审计的论文理解稿：

1. 用一句话写出论文主张，避免直接复制摘要。
2. 列出任务定义、现实动机和作者针对的具体失败模式。
3. 区分作者声称的贡献、论文实际展示的机制和实验已支持的结论。
4. 分开梳理训练阶段、推理阶段、监督信号、信息流和梯度方向；正文未说明的内部结构保持未知，不自行补全。
5. 摘出主要定量结果、消融、定性证据、异常点、成本和边界。
6. 记录需要原作者确认但不影响当前制作的问题。若作者明确表示无需回答，不把这些问题升级成主线，也不把猜测写进 PPT。

### 证据台账

先核查论文主张、方法、主结果及其引用的补充证据，为核心或拟使用的 `Figure / Table / Equation` 建立台账，至少包含：

- 编号与原文定位。
- 它支持的具体主张。
- 在目标投影尺寸下是否可读。
- 去向：`main / optional / backup / omit`。
- 处理方式：原图、裁切、放大拆分、由数据重绘，或仅用于解释的忠实示意图。
- 若省略，写明理由。

Figure 1、主结果表、关键消融、核心公式及影响主张的反例必须被明确决定去向；是否放主讲取决于叙事职责和可读性，不取决于是否容易排版。按主张依赖补读相应附录；短篇 Oral 不必把所有辅助推导逐式抄入台账。记录实际核查范围，用户要求完整覆盖时才扩展为全量清单，不把未读补充材料宣称已审阅。

## 先写逐页内容地图

先按 `ppt-contract.md` 的同一份 `slide-plan.md` 做内容预检，不另建一套字段近似的地图。使用 `## S01` 稳定 ID，以及 `role / title / claim / evidence / next`；用 `page_role` 表示论证职责，`density_mode` 表示文字、公式、正式图、混合证据或转场。`role` 支持 `main / optional / backup`，PPTX 备注标记与之相同。

时长与可跳过条件按需写在该页补充说明中；移交给他人主讲时再补充完整讲法。不需要让用户逐页确认常规内容判断；尚未授权的立场选择必须先解决，其余在用户已授权范围内继续制作。

每页只承担一个主要阅读任务，但可以包含多种互相依赖的证据。结果页表达有证据的作者式判断；定义、方法、设置页可用具体名称（如 Query prototype construction）或问题，不强造结论口号。

导航页不是默认必需。仅当章节关系较复杂、时长较长，或中途需要帮助听众重定位时使用；短篇 Oral 可通过稳定章节标签和标题链完成导航。

## 单篇论文的内容检查清单

以下用于检查理解与证据，不是一项一页的目录或固定顺序。先按实际问题和贡献取舍，可先展示关键现象再回溯方法；没有的内容不补造，收尾不强制独立边界页或未来工作页：

1. 任务与问题：听众先理解研究对象及困难。
2. 背景与动机：只补充理解贡献所需的概念和现实失败模式。
3. 贡献／研究地图：较早告诉听众本文改变了什么。
4. 相关工作发展：按理解贡献所需选择真正构成演进关系的代表工作，以原图或清晰局部图解释“已有进展 → 仍有缺口”，不做作者名堆叠。
5. 整体框架：先让听众知道模块关系、训练／推理位置和主信息流。
6. 核心方法：按“总览 → 机制／直觉 → 精确定义与公式”逐层深入。
7. 实验协议：数据集、任务设置、比较对象和指标只保留理解证据所需的信息。
8. 主结果：优先展示能直接支持核心主张的表或图。
9. 消融与机制验证：回答增益来自哪里、关键设计是否必要。
10. 定性结果、失败案例、稳健性或成本：按论文证据选择，不为凑结构而虚构。
11. 作者式结论：回到问题、贡献、证据和边界。
12. Backup：完整表格、额外消融、推导、实现细节和高概率问答证据。

若论文没有某类证据，删除对应环节；若贡献复杂，可以拆开。不要为了遵守骨架而制造论文中不存在的内容。

## 原始证据与解释性重绘

严格区分两种图：

- **证据图**：论文原图、原表、用户提供的正式图片，或根据原始数据准确重绘的图表。它用于证明结果，优先保持来源保真。
- **解释图**：为帮助听众理解机制而重新组织的流程图、结构图或局部示意。它可以使用原生 PPT 对象，但必须忠实于论文，且不得冒充实验结果。

默认规则：

- 用户已经提供清晰正式图时，优先裁切、放大、分步展示和加外部标注，不因“统一风格”“方便编辑”或“容易生成”而重画。
- 原图标签在目标尺寸不可读时，不得把模糊缩略图留在主讲页；应寻找更高分辨率版本、分区裁切、拆页、从数据准确重绘，或移入 Backup。
- 解释图只在它能回答明确理解问题时绘制，例如模块依赖、信息流、teacher／student 关系或训练阶段。通用矩形、等权节点和装饰箭头不是机制解释。
- 所有引用论文图、表和结论保留可见来源。局部裁切不能让图例、坐标、比较口径或方法身份失真。

## 方法页与公式页

复杂方法可从以下三个维度解释；它们不是固定三页或三个等权模块，已有框架与原图足够时不重复拆解：

1. **整体位置**：该组件接收什么、输出什么、在系统何处发生。
2. **机制与直觉**：为什么需要它，哪些对象或关系被改变。
3. **精确定义**：关键变量、公式、损失和优化方向。

布局必须表达依赖关系。稳定角色应固定位置和颜色，例如 support／teacher 在左，query／student 在右；跨页不得互换。箭头必须有真实语义，起点、终点、方向和标签均可解释；若没有流向或依赖，就不要使用箭头。

公式必须作为真正的数学对象排版，不用正文字符拼接，也不把低清公式截图放大。每个关键公式至少说明：输入或变量角色、该式完成的操作、它与上一层机制的关系。避免孤立大公式、巨大灰底公式框和公式与正文互相遮挡。

公式须在最终交付媒介的实际渲染结果中验收：HTML／Marp 网页版在浏览器中检查，PPTX 使用演示文稿渲染器，交付 PDF 时另查 PDF。不得仅为满足另一媒介的检查条款额外生成文件。LaTeX 源码正确不保证目标渲染正确；方框、命令字面量、错位上下标或异常字体必须修复并重新渲染。

## 投影密度与“去 AI 感”

大屏幕允许一页包含较多信息，但密度应来自证据和关系，而不是文本堆积。每页仍需有清晰的第一阅读入口、主证据和次级解释。

重点避免以下常见“AI 成品感”：

- 连续多页复制“口号标题 + 三张圆角卡片 + 一句总结”。
- 把所有内容机械改写为三个短 bullet，或用通用栏目替代具体操作与证据；key insight 等词不是禁词，问题是有无实际信息。
- 为填空添加无来源示意、随机渐变、装饰箭头、图标墙和无职责照片。
- 用统一等大的模块框表示本应有主次、方向或拓扑的机制。
- 一页只剩大标题和稀疏卡片，下一页又把完整论文表格缩成不可读的小图。
- 因生成方便连续复制页面外壳；有意保持同组实验布局以便比较不属于此问题。

结构化高密度可以通过主图 + 局部放大、公式 + 角色解释、表格 + 直接标注、机制图 + 定义、总览 + 关键分支实现。官方模板存在时，保留其母版、Logo 和基本色彩；个人品味主要控制叙事、页面职责、证据尺度和细节质量，不强行覆盖成另一套 UI。

## 主讲、可跳过与 Backup

- `main`：缺少后会破坏核心论证链的页面。
- `optional`：用于延展背景、次要实验或较深公式；跳过后上下页仍能自然衔接。
- `backup`：回答高概率问答的完整表格、更多消融、推导、实现细节和补充图。

主 deck 可以诚实呈现例外、下降点和限制，但语气保持作者式说明：先说证据支持什么，再说适用边界。详细 reviewer-style 质疑、未证实推断和不影响主结论的疑问优先进入备注或 Backup。未知信息明确标为未知，不替作者发明回答。

## 演讲备注与移交

用户要求完整逐页讲稿、双语版本或压缩讲法时，另读 [speaker-script-workflow.md](speaker-script-workflow.md)，沿用实际 deck 的当前页序。下列简短备注不能冒称完整讲稿；单独整理讲稿不默认修改 PPT 或备注。

当制作者不是最终主讲人时，每页备注至少包含：

- 推荐阅读顺序和 `1–2` 句自然讲法。
- 图、表、公式和外部论文的来源定位。
- 本页建议时长，以及是否可跳过。
- 关键术语、容易误解的边界和可接受的问答范围。

听众必须看到的关键事实不能只藏在备注里。移交给他人时，检查仅凭论文、PPT 和备注能否解释每页为何存在、证据支持什么、跳过后如何衔接。真实主讲人试讲或目标投影设备未提供时，明确尚未验证，不将助手自行通读称为已完成真人“换人主讲测试”。

## 视觉 QA 与版本纪律

下列项目按 `qa-rubric.md` 的任务范围执行；完整新作全量检查，局部修订只复检受影响页面、对象及连带变化，记录沿用的旧证据：

1. 渲染本次检查范围内的幻灯片，以 `100%` 成品尺寸检查正文、轴标签、图例、公式、单位、引用和图片清晰度；完整新作覆盖全部页面。
2. 用全篇缩略图检查叙事节奏、页面轮廓重复、章节重定位和证据密度变化。
3. 检查所有公式是否出现未解析命令、空方框、异常字体、非等比拉伸、上下标错位或遮挡。
4. 检查所有箭头、连接线、裁切边缘和叠放层级；箭头不得指向错误对象，截图不得残留无关表头、断边或遮挡。
5. 检查官方母版、Logo、页眉页脚、页码、来源、占位符和封面信息；未填占位符必须在交付说明中明确，不能静默遗留。
6. 检查主结果表、关键 Figure、核心公式和例外结果是否都已按证据台账处理。
7. 每次重要修订保留上一版本并递增版本号；定向修改核对内容与渲染差异，确认未意外改变其他页。完整新作没有历史基线时，版本差分为“不适用”。工具只能批量导出时可以导出全套，但不因此增加无关的研究或反复检查。
8. 需要移交时检查备注完整性；能访问目标机器／投影环境时做兼容检查，不能访问则记录依赖与未验证项，不为环境未知虚构通过记录。

## 交付门禁

只有同时满足以下条件，才视为可交付：

- 论文主张、贡献、机制、证据和边界已经分开梳理。
- 核心及拟使用 Figure／Table／Equation 的证据台账完整，核查范围明确，影响主张的重要证据没有因疏漏被省略。
- 每页内容地图已预检并与成品比对，主讲／可跳过／Backup 有明确标记，必要的用户决定有来源。
- 相关工作用于解释发展与缺口，不是姓名或引用堆叠。
- 方法至少包含整体位置与机制解释；公式页可读且与机制相连。
- 主图、主表和公式在目标尺寸下可读，来源清楚。
- 标题与结论不夸大论文证据，未知信息未被补写成事实。
- 本次影响范围内的渲染、原尺寸、公式、箭头、遮挡与必要的全篇一致性检查已完成；完整新作全量验收，局部修订注明沿用证据，新作无历史基线时不要求版本差分。
